# ADR 0002. Сессия на устройстве: возврат в игру после перезапуска приложения

- **Статус:** Accepted (принято)
- **Дата:** 2026-09-26
- **Автор:** Denys Bohusevych (черновик — Claude Code)

## Контекст

Сессия игрока (`PlayerSession`: `gameId`, `playerId`, `token`) жила только в памяти `GameSessionManager`. Приложение, которое убила система (iOS при нехватке памяти, «энергосбережение» Android) или смахнул сам игрок, не могло вернуться в идущую игру: повторный вход по коду отвечает `WRONG_STATE`. Сервер при этом держит игрока: раскрывает его ищущим как `STALE_SIGNAL`, а заявка на него засчитывается по таймауту кода. Это сценарий из жизни: телефон в кармане полчаса, раунд идёт на улице.

Что важно для решения:

- **Токен — секрет.** Это bearer-токен: кто его знает, тот играет за игрока (шлёт координаты, делает заявки, голосует). Он живёт, пока игра есть на сервере: 30 мин после конца или 6 ч простоя (`GameJanitor`).
- **GDPR.** Координаты — персональные данные, на устройстве их хранить не нужно и нельзя.
- **Настройки клиента** из roadmap: имя игрока и адрес сервера между запусками.
- **Сервер авторитетен.** Клиент не должен сам решать, идёт ли игра: это знает только сервер.

## Решение

### Что хранится

| Ключ | Что | Когда пишется | Когда стирается |
|---|---|---|---|
| `session` | `SavedSession(serverUrl, PlayerSession)` одной JSON-записью (атомарно) | создание игры или вход | выход из игры, конец игры (`FINISHED`), сервер не знает игру или токен (401/404) |
| `playerName`, `serverUrl` | поля главного экрана | после успешного создания игры или входа | не стираются |

Координаты, снапшоты, коды находки на устройстве не хранятся. Секрет кода прячущийся снова получает в `MyState.catchCodeSecret` первого же снапшота.

### Где хранится

- `SecureStore` (`read` / `write` / `remove`) — интерфейс в `:clientCore` `commonMain`. Логика поверх него — `ClientStorage` там же: формат, чтение сессии, ошибки платформы считаются «ничего не сохранено». Приложение из-за хранилища не падает.
- Реализации — в `:composeApp`, биндинг в платформенном Koin-модуле:
  - **Android — `AndroidSecureStore`.** Каждое значение шифруется AES-256-GCM ключом из Android Keystore. Ключ не экспортируется и в памяти приложения байтами не бывает. В приватные `SharedPreferences` (`hovanki_secure`) попадает только шифротекст с IV. Имя ключа — associated data, поэтому значения нельзя переставить между ключами. Резервное копирование в приложении уже выключено (`android:allowBackup="false"`), а скопированный файл без ключа бесполезен. Запись через `commit()`: сессия должна лечь на диск до того, как игрок смахнёт приложение.
  - **iOS — `KeychainSecureStore`.** Generic password в Keychain (service `app.hovanki`, account = ключ) с `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`:
    - читается после первой разблокировки: раунд идёт с заблокированным экраном;
    - не попадает в бэкапы и на новый телефон.

    Keychain переживает удаление приложения. Поэтому при первом запуске после установки (флаг в `NSUserDefaults`, который удаляется вместе с приложением) старые записи стираются: переустановленное приложение не пытается вернуться в давнюю игру.
- Боты e2e держат то же хранилище в памяти «телефона» (`PhoneStorage`): оно переживает `killApp()`, как Keystore/Keychain.

### Как приложение возвращается в игру

`GameSessionManager.resumeSavedGame()` вызывается при старте UI (`onAppStart`: `MainActivity.onCreate`, в том числе после пересоздания процесса системой; `mainViewController()` на iOS), один раз на процесс.

1. Сохранённая сессия сразу становится текущей с `isResuming = true`. Игрок видит «Возвращаемся в вашу игру…», а не главный экран.
2. Проверка — обычный `POST /sync` с `Authorization: Bearer <token>` через тот же `PollingGameConnection`, отдельного эндпоинта нет:
   - **игра идёт** (LOBBY, HIDING, SEEKING) — экран фазы; опрос, `LocationOutbox`, геолокация и `BackgroundTracker` поднимаются заново, прячущийся снова может показать код;
   - **игра закончилась** (`FINISHED`) — сессия стирается, главный экран с сообщением «Игра, в которой вы были, закончилась, пока приложение было закрыто»;
   - **игры нет** (404: удалена `GameJanitor`, сервер перезапущен) **или токен не принят** (401) — сессия стирается, главный экран с сообщением «Не удалось вернуться в игру: на сервере её больше нет»;
   - **нет сети** — повторы с тем же backoff, что в игре, сессия не стирается; на экране «Нет связи с сервером» и кнопка «Выйти из игры».
3. После возврата сервер сам снимает раскрытие `STALE_SIGNAL`, как только приходят свежие точки.

**Сервер не менялся.** `sync` с токеном принимает вернувшегося игрока в любой фазе, для завершённой игры отдаёт `FINISHED`, для удалённой — 401/404. Протокол не менялся: ни новых полей, ни эндпоинтов.

Для UI-автоматизации есть debug-параметр запуска `forgetSavedGame`: сценарии на устройствах начинают с главного экрана, даже если прошлый сценарий оставил игру. Release-сборки параметры запуска не читают.

## Выбор библиотеки

| Вариант | Android | iOS | Итог |
|---|---|---|---|
| `androidx.security:security-crypto` (`EncryptedSharedPreferences`) | шифрование через Keystore | — | с 1.1.0 все API помечены deprecated, Google рекомендует Keystore напрямую |
| KVault | `EncryptedSharedPreferences` | Keychain | на Android та же deprecated-зависимость; редкие релизы |
| multiplatform-settings | `SharedPreferences` без шифрования | `KeychainSettings` (`@ExperimentalSettingsImplementation`) | на Android шифровать всё равно самим; Keychain-часть экспериментальная, последний релиз 1.3.0 — ноябрь 2024 |
| DataStore + Tink | шифрование Tink | — | тяжёлые зависимости ради одной строки; iOS всё равно отдельно |
| **Свои тонкие реализации на платформенных API** | Keystore + `SharedPreferences`, ~70 строк | Security.framework, ~120 строк | **выбрано**: без зависимостей, атрибуты доступа под наш случай, API платформ стабильны годами |

Цена решения:
- свой код вокруг криптографии и Keychain;
- interop с Security.framework собирается только в macOS CI;
- юнит-тестов платформенных реализаций нет: нужен настоящий Keystore или Keychain. Их проверяет слой устройств — сценарий `restart` на Android-эмуляторе и iOS-симуляторе ([e2e.md](../e2e.md)). Логика восстановления покрыта `commonTest` в `:clientCore` (`SessionResumeTest`, `ClientStorageTest`) и сценариями ботов (`RestartTest`).

## Последствия

- Убитое приложение возвращается в игру. Игрок, пока приложение было мертво, раскрыт как `STALE_SIGNAL`, но после возврата снова прячется и сам показывает код. Заявка не засчитывается молча по таймауту.
- Токен лежит на устройстве не дольше игры: стирается при выходе, конце игры и отказе сервера. Нужен разблокированный телефон, а на Android ещё и ключ из Keystore этого устройства.
- Главный экран помнит имя и адрес сервера (пункт roadmap «Настройки клиента»).
- Новые данные в хранилище — через `ClientStorage` с понятным правилом стирания; координаты туда не пишем.

# ADR 0008. Админка: роли, вход сотрудников, модерация

- **Статус:** Accepted (принято)
- **Дата:** 2026-09-28
- **Автор:** Denys Bohusevych (черновик — Claude Code)
- **Дополняет:** [ADR 0004, раздел 9](0004-accounts-friends-chat.md#9-модерация) — жалобы теперь есть кому и чем разбирать.

## Контекст

Жалобы на сообщения копятся в таблице `reports`, но разбирать их некому и нечем: только SQL на сервере ([ADR 0004](0004-accounts-friends-chat.md#9-модерация)). Нельзя ни забанить, ни запретить писать в чат, ни сменить оскорбительный ник, ни ответить на письмо «не могу войти, удалите мой аккаунт». App Store и Google Play для приложений с чатом требуют, чтобы на жалобы реагировали.

Нужна админка: страница для сотрудников и эндпоинты под ней. Это самые опасные права в системе, поэтому вместе с ней — роли и отдельный, более строгий вход.

Ограничения:
- **GDPR и принцип минимума.** Сотрудник видит только то, без чего нельзя разобрать жалобу или обращение. Координаты, маршруты, чат вне жалоб, пароли, токены — никогда ([ADR 0007](0007-game-history-and-routes.md), [metrics.md](../metrics.md#кто-и-как-смотрит)).
- **Один сервер на t3.micro** ([deploy.md](../deploy.md)): никаких отдельных сервисов, фреймворков фронтенда и сборки JS.
- **Протокол игры совместим со старыми клиентами** (CLAUDE.md).

## Решение коротко

| Что | Решение |
|---|---|
| Где | веб-страница `/admin` на том же сервере: статические HTML, CSS и JS без сборки и сторонних библиотек; JSON-эндпоинты `/api/v1/admin/*` |
| Роли | `users.role`: `PLAYER` (по умолчанию), `MODERATOR`, `ADMIN`. Проверяется на каждом запросе: снятая роль действует сразу |
| Кто назначает | модераторов — админ в админке; админов — только оператор сервера, SQL-запросом ([deploy.md](../deploy.md)) |
| Вход | пароль аккаунта + код TOTP (Google Authenticator, 1Password и т. п.). Первое подключение приложения-аутентификатора — только с кодом из письма на подтверждённый email |
| Сессия | отдельная админ-сессия: cookie `__Host-hovanki-admin` (`HttpOnly`, `Secure`, `SameSite=Strict`), 30 минут без действий, 8 часов максимум. Токен аккаунта из приложения админских прав не даёт |
| CSRF | `SameSite=Strict` и обязательный заголовок `X-Hovanki-Admin: 1` на каждом админском запросе (чужой сайт не может его поставить без CORS, а CORS сервер не разрешает) |
| Секреты TOTP | в базе, зашифрованы AES-GCM ключом `HOVANKI_ADMIN_SECRET_KEY` из `.env`. Нет ключа — админка выключена |
| Журнал | каждое действие сотрудника и каждый показ email: кто, когда, что, над кем, причина. 1 год |
| Санкции | бан (вход и игра с аккаунтом) и запрет на чат, на срок или навсегда, с причиной |

## 1. Что видит и делает сотрудник

| | Модератор | Админ |
|---|---|---|
| **Жалобы:** очередь, текст сообщения, автор, кто пожаловался, сколько жалоб на автора за 90 дней и от скольких людей | ✓ | ✓ |
| Разобрать жалобу: отклонить, запретить чат, бан, сменить ник. Закрываются все жалобы на это сообщение | ✓ | ✓ |
| **Пользователи:** поиск по нику или id, карточка (ниже) | ✓ | ✓ |
| Поиск по точному email (обращения в поддержку), показ email целиком — с причиной, в журнал | — | ✓ |
| Запрет на чат, бан до 30 дней, снять их | ✓ | ✓ |
| Бан дольше 30 дней или навсегда, снять его | — | ✓ |
| Сменить ник на случайный (`player-…`) | ✓ | ✓ |
| Выйти на всех устройствах (угнанный аккаунт) | — | ✓ |
| Удалить аккаунт (по письменному запросу) | — | ✓ |
| **Игры сейчас:** фаза, игроки, гости, сколько идёт, радиус зоны | ✓ | ✓ |
| Завершить игру | — | ✓ |
| **Цифры:** регистрации, активные игроки, игры, баланс, жалобы, состояние сервера | ✓ | ✓ |
| **Сотрудники:** список, назначить и снять модератора, сбросить его TOTP | — | ✓ |
| **Журнал** действий | — | ✓ |

**Карточка пользователя:** ник, id, роль, дата регистрации, язык; email подтверждён или нет, сам адрес скрыт (`d•••@gmail.com`); сколько игр и когда последняя; сколько устройств вошло и когда последний раз; включено ли «Сохранять маршруты» (только да или нет); жалобы на него и от него; сколько людей его заблокировали; баны и запреты на чат.

**Никогда:** пароль и его хэш, токены, коды из писем, координаты и маршруты (в том числе сохранённые), чат вне жалоб, вход «под пользователем». Центр зоны игры не показывается: это позиция хоста.

**Цифры** — только агрегаты; среднее по меньше чем 5 играм или игрокам не показывается (правило [metrics.md](../metrics.md#кто-и-как-смотрит)).

**Над сотрудниками** санкции не действуют: сначала админ снимает роль. Над собой — ничего.

## 2. Вход

```
POST /admin/login {login, password}
  → неверно, не сотрудник, лимит — одинаковый ответ WRONG_CREDENTIALS
  → challenge (5 минут, в памяти) + что дальше: TOTP или ENROLL
TOTP:   POST /admin/login/totp {challenge, code}               → сессия (cookie)
ENROLL: письмо с кодом на подтверждённый email
        POST /admin/enroll {challenge, emailCode}              → секрет, otpauth-ссылка, QR
        POST /admin/enroll/confirm {challenge, code}           → сессия (cookie)
```

- **Почему код из письма при подключении.** Без него тот, кто узнал пароль сотрудника раньше, чем тот подключил аутентификатор, подключил бы свой. Email должен быть подтверждён (`EMAIL_NOT_VERIFIED` иначе).
- **TOTP** — RFC 6238: SHA-1, 6 цифр, 30 секунд, допуск ±1 шаг; тот же `Totp` из `:shared`, что и коды находки. Каждый шаг принимается один раз (`staff_totp.last_step`): подсмотренный код не сработает второй раз.
- **Лимиты.** Пароль — как вход в приложении (по IP и логину). Коды TOTP — 5 попыток на challenge и не больше 10 за 15 минут на сотрудника.
- **Потерял телефон.** Модератору TOTP сбрасывает админ; админу — оператор сервера SQL-запросом ([deploy.md](../deploy.md)).
- **Выключатель.** Нет `HOVANKI_ADMIN_SECRET_KEY` — все `/api/v1/admin/*` отвечают 404, страница пишет, что админка выключена.

## 3. Санкции

| | Бан | Запрет на чат |
|---|---|---|
| Что делает | удаляет все сессии аккаунта; вход в приложение — `403 ACCOUNT_BANNED` со сроком (`ApiError.untilMillis`); в текущей игре писать в чат нельзя | сообщения в чат — `403 CHAT_MUTED` со сроком; играть можно |
| Срок | дни или навсегда | дни |

- Текущая игра забаненного идёт до конца (его игровой токен не отзывается: убрать игрока посреди раунда — отдельное правило игры). Если нужно — админ завершает игру.
- **Гостя забанить нельзя**: у него нет аккаунта. Это ограничение принимаем; дальше — репутация публичных лобби ([roadmap](../roadmap.md)).
- Удалив аккаунт, забаненный может зарегистрироваться заново. Хранить email забаненных после удаления аккаунта — отдельное решение ([roadmap](../roadmap.md)).
- Старые клиенты не знают новых причин и видят обычную ошибку `FORBIDDEN`; `untilMillis` — новое поле с дефолтом.

## 4. Схема

Миграция `V4__admin.sql`:

| Таблица | Что | Срок |
|---|---|---|
| `users.role` | `PLAYER` / `MODERATOR` / `ADMIN` | пока аккаунт |
| `staff_totp` | секрет TOTP (зашифрован), подтверждён ли, последний принятый шаг; `ON DELETE CASCADE` | пока аккаунт или до сброса |
| `admin_sessions` | хэш токена, сотрудник, время; `ON DELETE CASCADE` | 8 часов, удаляются `DataRetention` |
| `sanctions` | бан или запрет на чат: срок, причина, кто выдал и снял; `ON DELETE CASCADE` | пока аккаунт; закончившиеся — год после конца |
| `reports.resolved_at/_by`, `resolution` | как закрыта жалоба | 90 дней, как сама жалоба |
| `admin_audit` | журнал: время, кто (id и ник), действие, над кем, объект, причина. Без внешних ключей: журнал переживает удаление аккаунтов | 1 год |
| `email_codes.purpose` | + `STAFF_ENROLL` | 15 минут |

Журнал хранит id пользователя, над которым было действие, и после удаления его аккаунта: это защита и самого пользователя, и сервиса (кто и почему его забанил), срок ограничен годом. Причину сотрудник пишет коротко, без лишних личных данных.

## 5. Защита страницы

- `Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; frame-ancestors 'none'; base-uri 'none'; form-action 'self'`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`; ответы API админки — `Cache-Control: no-store`.
- Текст жалоб, ники и причины — чужой ввод: страница вставляет их только как текст (`textContent`), никогда как HTML. QR приходит матрицей и рисуется на странице.
- Никаких сторонних скриптов, шрифтов и CDN.
- Сессия проверяется на каждом запросе по базе: роль снята, сессия истекла или удалена — 401.

## 6. API

Все маршруты — `/api/v1/admin/...`, заголовок `X-Hovanki-Admin: 1`, cookie сессии (кроме входа). Полный список — [architecture.md](../architecture.md#api). DTO — `shared/.../protocol/Admin.kt`: e2e-тесты ходят в админку тем же Kotlin-кодом.

## Последствия

- Жалобы разбираются на странице, а не SQL-запросами; каждое действие видно в журнале.
- Перед запуском на сервере нужно: сгенерировать `HOVANKI_ADMIN_SECRET_KEY`, назначить первого админа SQL-запросом, подтвердить его email ([deploy.md](../deploy.md)).
- Потерянный ключ `HOVANKI_ADMIN_SECRET_KEY` — все сотрудники подключают TOTP заново (секреты не расшифровать), остальное не страдает.
- Правила сообщества и политика конфиденциальности должны назвать: жалобы разбирают сотрудники, за нарушения — запрет на чат и бан, журнал действий хранится год.
- Дальше ([roadmap](../roadmap.md)): фильтр слов в чате, бан по email после удаления аккаунта, смена ника самим игроком, уведомление сотрудников о новых жалобах.

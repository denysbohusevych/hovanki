# ADR 0022. Рейтинг города: город — где телефон сейчас

- **Статус:** Accepted (сервер, протокол, `:clientCore` и экраны в коде; на телефонах ещё не пробовали)
- **Дата:** 2026-10-07
- **Автор:** Denys Bohusevych (черновик — Claude Code)
- **Дополняет:** [ADR 0020](0020-leaderboard.md) (рейтинг, раздел 3 «„Друзья“ вместо „Киева“»), [ADR 0004](0004-accounts-friends-chat.md) (аккаунты, сроки хранения), [ADR 0007](0007-game-history-and-routes.md) (история игр)

## Контекст

В макете у рейтинга вкладки «Остання гра / Київ / Світ». В ADR 0020 «Київ» заменили на «Друзі»: чтобы считать рейтинг города, надо знать город игрока, а сервер его не хранит, и решение о новом персональном данном отложили.

Первый вариант этой ветки — город выбирает сам игрок из списка. Denys решил иначе: город обозначается по тому, где игрок находится сейчас.

## Решение коротко

| Вопрос | Решение |
|---|---|
| Откуда город | **Телефон** определяет его по своему текущему положению: одна отметка GPS (точность до 3 км хватает), ближайший центр города из списка в пределах его радиуса (`Cities.at` в `:shared`). На сервер уходит **только id города**, координаты — нет. Не в городе из списка — города нет (`null`) |
| Когда | Каждый раз, когда игрок открывает вкладку «Рейтинг» (`CityLocator.locate` в `:clientCore`), и по кнопке «Спробувати ще». Без разрешения на геопозицию — ничего: вкладка города предлагает его дать. Сменился город — приложение отправляет новый, рейтинг города перечитывается |
| Какие города | Фиксированный список `Cities.ALL`: областные центры вне оккупации и несколько больших городов (25), у каждого центр и радиус (20 км; Киев, Кривой Рог — 30 км с пригородами; Харьков, Одесса, Днепр — 25 км). Радиусы не пересекаются (`CitiesTest`). id латиницей (`kyiv`, `lviv`, …), названия — в ресурсах приложения на трёх языках. Новые города можно добавлять, id не переименовывать и не удалять |
| Где хранится | Колонка `users.city` (миграция `V15`), `null` — не определён. Живёт вместе с аккаунтом: удалил аккаунт — города нет. Отдельного срока хранения не нужно: это последнее значение, без истории |
| Маршрут | `POST /api/v1/me/city` с `CityRequest(city)`, `null` — забыть; отвечает `UserProfile` (в нём `city`). Неизвестный id — 400. Сервер верит телефону: подделать город можно, как и любой клиентский ввод; ставка — место в рейтинге за неделю |
| Вкладка | `LeaderboardScope.CITY`: все, у кого **сейчас** тот же город, по очкам этой недели, как «Мир» — первые 50 и своя строка `me`, `nextAbove`, `rankChange`. В ответе `city`; без города — пустой ответ с `city = null` |
| Прошлая неделя | Для `rankChange` — тоже по сегодняшним городам (как «Друзья» — по сегодняшнему списку друзей). Переехал — сравнение с прошлой неделей нового города |
| Порядок вкладок | «Остання гра / Київ / Друзі / Світ»: город на втором месте, как в макете; вкладка называется городом игрока, пока его нет — «Місто» |

## Приватность

- **Координаты не уходят с телефона.** Город считается на телефоне, на сервер — только его id. Сервер не получает и не пишет положение вне игры.
- **Это новое данное о местоположении, но грубое:** город, последний, без времени и истории. Экран согласия на геопозицию говорит об этом («а ещё раз, когда открываешь рейтинг города…»), профиль показывает город и откуда он.
- **Не хочешь — не давай геопозицию:** без разрешения город не определяется. Уже определённый остаётся до следующего открытия рейтинга в другом месте.
- **Что видят другие.** Сам город в ответах о других игроках не передаётся. Его видно косвенно: игрок попадает в рейтинг своего города, и другие игроки этого города видят там его ник и очки за неделю — то же, что и так видно во «Мире».
- **Персонал** город не видит: в админке его нет.
- Гости, забаненные и удалённые — как в ADR 0020: гостей нет, забаненных не показываем, удалённые уносят свои строки.

## Как считается

`LeaderboardService` для `CITY` читает город вызывающего (`LeaderboardRepository.cityOf`), затем те же строки `game_results`, что и для «Мира», с условием `users.city = :city`. Агрегация и правило очков те же (`LeaderboardRules`). Индекса по `users.city` нет: запрос идёт от строк `game_results` за две недели (индекс `V14`), а `users` подтягивается по ключу.

## Последствия

- Протокол обратно совместим: новое поле `UserProfile.city`, новое поле `LeaderboardResponse.city`, новое значение `LeaderboardScope.CITY` (старые приложения его не запрашивают и в ответах не получают), новый маршрут.
- Приложение: `CityLocator` (`:clientCore`), вкладка города в «Рейтинге» (ищем / дай геопозицию / не нашли / ты не в городе из списка), строка «Місто» в профиле (только показ), строка в экране согласия на геопозицию.
- Тесты: `CitiesTest` (`:shared`: город по точке, радиусы не пересекаются), `CityLocatorTest` (`:clientCore`: на сервер только город, грубая отметка пропускается, без разрешения и без отметки — ничего), `LeaderboardServiceTest` (вкладка города, без города, смена города, маршрут `/me/city`), `HttpHistoryApiTest`, e2e `LeaderboardTest`.
- Открыто: города за пределами Украины, рейтинг города за все времена, очки по городу, где прошла партия (сейчас считается город игрока сейчас, а не место игры).

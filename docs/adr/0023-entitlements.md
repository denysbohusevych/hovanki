# ADR 0023. Основа монетизации: платные права аккаунта

- **Статус:** Accepted (сервер, протокол, админка и строка в профиле в коде; за правами пока ничего не закрыто, платежей нет)
- **Дата:** 2026-10-07
- **Автор:** Denys Bohusevych (черновик — Claude Code)
- **Дополняет:** [ADR 0004](0004-accounts-friends-chat.md) (аккаунты), [ADR 0008](0008-admin.md) (админка), [ADR 0013](0013-quests-sparks-and-sensors.md) (искры и перки не продаются)

## Контекст

Модель монетизации ещё не выбрана. Кандидаты за пейволом: премиум-хост (больше игроков, большая зона), стили карт, оформление (аватары, цвета, рамки на итогах), записи игр дольше 90 дней, карточки сторис без водяного знака. Что бы ни выбрали, нужна одна основа: сервер знает, какие платные вещи есть у аккаунта, приложение их показывает, сотрудник может выдать их без оплаты (тестировщику, для промо, вместо возврата). Платежей пока нет.

## Решение коротко

| Вопрос | Решение |
|---|---|
| Что такое право | `Entitlement` в `:shared` (`protocol/Entitlements.kt`): `PREMIUM_HOST`, `MAP_STYLES`, `COSMETICS`. У каждого строковый `id` (`premium_host`, …). Значения только добавляются |
| Кто решает | Только сервер. Таблица `entitlements` (V16): аккаунт, право, источник (`ADMIN`; потом магазины), когда выдано, до когда (`NULL` — навсегда), кто выдал. Одна строка на аккаунт и право; повторная выдача ставит новый срок |
| Что видит приложение | `UserProfile.entitlements` — список `id` активных сейчас прав (по умолчанию пустой). Строки, а не enum: старое приложение пропустит незнакомое право, а не упадёт на чтении профиля. `UserProfile.has(Entitlement)` и `knownEntitlements` в `:shared` |
| Проверка на сервере | `EntitlementRepository.has(user, entitlement, now)`; отказ — `ErrorCode.FORBIDDEN` + новая `ErrorReason.ENTITLEMENT_REQUIRED` (старые клиенты читают незнакомую причину как `null`). Пока ни один маршрут её не отдаёт |
| Выдача | Админка, карточка аккаунта, раздел «Платное»: «Выдать платное» (право, дни 1…3650 или навсегда, причина) и «Забрать» (причина). Только админы, не себе; в журнал `GRANT_ENTITLEMENT` / `REVOKE_ENTITLEMENT` в той же транзакции. Модераторы видят, но не выдают |
| Профиль | Карточка «Премиум» со списком прав, только если они есть. Замка и экрана «Получить» пока нет: закрывать нечего |
| Гости | Прав нет: права живут на аккаунте |
| Хранение | Персональные данные: уходят с аккаунтом (`ON DELETE CASCADE`), `DataRetention` удаляет право, как только его срок кончился. История выдач — в журнале админки (срок журнала) |

## Что не продаём

Ничего, что даёт преимущество в партии: искры, перки, подсказки, радар, больше времени на поиск (ADR 0013, без pay-to-win). Право `PREMIUM_HOST` меняет только то, какую игру хост может собрать, и одинаково для всех её игроков.

## Как закрыть фишку правом (когда решим)

1. Сервер: там, где хост выбирает настройку, — `entitlements.has(...)`, иначе `GameException(FORBIDDEN, …, ENTITLEMENT_REQUIRED)`. Проверка только при выборе, идущая игра сохраняет свои настройки (как `FEATURE_DISABLED`).
2. Приложение: `profile.has(...)` — показать замок вместо переключателя; ответ `ENTITLEMENT_REQUIRED` — тот же замок, не ошибка.
3. Новое право — новое значение `Entitlement` (и строка в админке `ENTITLEMENT` в `admin.js`, и название в профиле).

## Платежи потом

App Store и Google Play требуют их встроенные покупки для цифровых товаров. Тогда: новый `EntitlementSource` (`APP_STORE`, `GOOGLE_PLAY`), сервер проверяет чек сам (или через RevenueCat, он покрывает обе платформы и шлёт вебхуки) и пишет ту же строку `entitlements` со сроком подписки. Приложение и проверки не меняются: они смотрят только на право.

## Отличия от плана

План (таблица планов, п. 9) предлагал то же. Не сделано: замок и экран «Получить» в приложении — появятся вместе с первой закрытой фишкой.

## Изменение (2026-10-07): стили карт бесплатны

Тёмная, минимал, «Авто», 3D-дома и рельеф ([ADR 0025](0025-map-styles-and-height.md)) бесплатны для всех, с аккаунтом и без (решение Denys). `MAP_STYLES` пока ни к чему не привязано; если им что-то закроют — стили сверх этих.

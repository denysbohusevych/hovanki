# Лаборатория радио: настройки каждого опыта

Точные настройки для выхода 1: один iPhone (метка `A`) и Мак. Что и зачем мы проверяем — в [radio-lab.md](radio-lab.md), §1 и §8. Здесь только как проводить.

Большинство опытов проходят на столе. Носить телефон нужно только в E5 (карман) и E7 (расстояния), поэтому они идут последними.

## Перед каждым опытом

**Стол.** Мак и телефон лежат в 1 м друг от друга, телефон экраном вверх. Если в опыте сказано иначе — как в опыте.

**Мак.** Каждый опыт — новый запуск:

```bash
e2e/mac-beacon/run.sh --lab <ключи из опыта>
```

Дождись `Bluetooth: on` и `clock: … ms`.

**Телефон.**
- Bluetooth включён в **Настройки → Bluetooth**, не в Пункте управления.
- В карточке Radio первая строка — `Bluetooth ON`.
- **Lab running** включено, метка **A**, в шапке есть `clock +… ms`.

**Все переключатели, которых нет в таблице опыта, выключены.** Особенно важно: проба overflow и **As a hider** одновременно **не** включаются, кроме опытов, где это сказано. Обе рекламы идут в одну маску и путают результат.

## После каждого опыта

1. На Маке нажми `q`.
2. На телефоне **Export** → AirDrop на Мак → **Clear**. Именно **Clear**: каждый экспорт выгружает журнал с самого запуска, без **Clear** следующий файл повторит предыдущий.
3. Разложи файлы по папке опыта (`e1b`, `e2`, …):

   ```bash
   mkdir -p e2e/build/lab/e2
   mv ~/Downloads/hovanki-lab-A-*.jsonl e2e/build/lab/e2/
   mv e2e/build/lab/hovanki-lab-mac-*.jsonl e2e/build/lab/e2/
   ```

4. Сведение (можно и в конце, по каждой папке). `echo`, а не `ls`: `ls` ставит между файлами перевод строки, и они приходят как одно имя.

   ```bash
   ./gradlew :e2e:lab --args="merge $(echo e2e/build/lab/e2/*.jsonl) --out e2e/build/lab/e2/merged"
   ```

**Метки мест.** Сценарии ставят метки вроде «рука» или «карман». В опытах на столе это не так, и это не страшно: матрица кармана (`carry.csv`) считается только для E5. В остальных опытах на метки мест не смотрим.

## E1b. Порядок бит и бит нашего сервиса (~6 мин, стол)

Продолжение E1. Шаблон `0x5A` читается одинаково при любом порядке бит, поэтому нужны одиночные биты.

| | |
|---|---|
| Мак | `run.sh --lab --sniff` |
| As in a game | вкл |
| As a hider | выкл (кроме шага 4) |
| Проба | по шагам |

1. Проба **bit 0**, минута на экране.
2. Проба **bit 7** (кнопки **+1**/**+10**), минута на экране.
3. Проба **bit 8**, минута на экране.
4. Проба **off**. Включи **As a hider** и заблокируй телефон на 2 минуты. Разблокируй.

**Что должно быть на Маке:**
- Шаг 1: маска `bit 0`. Если в эфире `01000000…`, порядок бит Янга верен. Если `80000000…`, порядок внутри байта обратный.
- Шаги 2 и 3 проверяют то же с другой стороны байта и на границе байтов.
- Шаг 4: маска из одного бита **114**. Это подтвердит, что 114 — бит нашего сервиса, а заблокированный прячущийся сейчас виден только им.

## E2. Маска переживает смену жетона (~5 мин, стол)

| | |
|---|---|
| Мак | `run.sh --lab --sniff` |
| As in a game | вкл |
| As a hider | выкл |
| Проба | **token** |

1. **Scenario** → **E2 mask survives a token change**.
2. Проба **token**. Запомни `probe token …` на экране.
3. **Change the token in 60 s** — и сразу заблокируй телефон, он остаётся на столе.
4. Через 3 минуты разблокируй, лаборатория на экране. **Next**, минута, **Finish**.

**Что должно быть:**
- Во время блокировки на Маке — `mask …: token <старый>`, в том числе после 60-й секунды.
- После разблокировки — `token <новый>`.
- В журнале телефона — `adv skipped_background` около 60-й секунды и `adv start` после разблокировки.
- Если маска пропала после 60 с, iOS погасила рекламу. Это плохой, но важный ответ.

## E3. Вибрация из фона (~8 мин, стол + одна попытка в кармане)

Мак не нужен.

| | |
|---|---|
| As in a game | по попыткам |
| Всё остальное | выкл |

Тест длится около минуты:
- 10 с на блокировку;
- 4 группы по 3 удара: 1 — Core Haptics, 2 — impact, 3 — уведомление с беззвучным звуком, 4 — уведомление без звука;
- между группами паузы по 5 с;
- в конце один удар «конец».

Перед первым тестом iOS спросит уведомления со звуком. Ответь **до** блокировки: отсчёт начнётся после ответа.

1. **На столе, As in a game вкл.** Нажми **Vibration test** и заблокируй. Слушай и смотри, какие группы жужжат. Через минуту разблокируй и нажми **Felt** с номерами услышанных групп.
2. **В кармане, As in a game вкл.** То же, но телефон в кармане. Считай группы, которые почувствовал.
3. **На столе, As in a game выкл.** То же. Ожидается тишина: без GPS iOS усыпляет приложение.

**Felt** жми сразу после каждой попытки, до следующей.

## E4. Экран, погашенный датчиком приближения (~12 мин, стол)

На столе датчик закрывается, если положить телефон **экраном вниз**: экран гаснет сам, телефон не блокируется.

| | |
|---|---|
| Мак | `run.sh --lab --sniff --advertise cafe0001` |
| As in a game | вкл |
| As a hider | вкл |
| Screen off by the proximity sensor | вкл |
| Pulse by the lab's loudest band | **haptics** |

1. Отметка **table_up** в карточке Marks. 1 минута экраном вверх, экран горит.
2. Отметка **table_down**. Переверни телефон **экраном вниз** на 10 минут. **Боковую кнопку не трогать.**
3. Переверни обратно, экран загорится. Отметка **table_up**.

**Что должно быть:**
- На Маке `hears <bench token>` все 10 минут без дыр. `bench token` виден в карточке Radio.
- Телефон должен вибрировать пульсом: он слышит Мак (`cafe0001`) рядом, это «горячо».
- В журнале телефона нет `did_enter_background`.
- Заряд в начале и в конце записан.

Если хочешь проверить в кармане: после шага 3 ещё 3 минуты с телефоном в кармане экраном к ноге. Перед этим отметка **pocket_front**.

## E6. iBeacon на заблокированном iPhone (~8 мин, стол)

Главный вопрос: слышит ли заблокированный iPhone маячок ищущего. От этого зависит «чутьё» из кармана.

| | |
|---|---|
| Мак | `run.sh --lab --ibeacon cafe0002` (без `--sniff` и `--advertise`) |
| As in a game | вкл |
| As a hider | вкл (он запускает ranging маячков) |

**Сначала проверка, 30 с.** На Маке не должно быть `advertising failed`. На телефоне во вкладке **Diagnostics** → Bluetooth должен появиться `cafe0002` с dBm.
- Если `cafe0002` нет — macOS не вещает iBeacon. Опыт пропускаем, завтра его сделаем с Android.

Если маячок слышно:
1. **Scenario** → **E6 / E9 iBeacon ranging while locked**.
2. Минута на экране.
3. Блокировка на 5 минут, телефон на столе.
4. Минута снова на экране.

**Что смотреть:** в `timeline.txt` — строки `rx cafe0002 … corelocation_ranging/ibeacon`. Идут ли они после блокировки, через сколько секунд пропадают, возвращаются ли после разблокировки.

## E5. Карман (~25 мин, с телефоном на себе)

Единственный опыт, где метки мест — это истина для классификатора кармана. Поэтому телефон кладёшь туда, куда говорит шаг, **до** нажатия **Next**.

| | |
|---|---|
| Мак | `run.sh --lab --sniff --advertise cafe0001`, на столе, в 2–3 м от тебя |
| As in a game | вкл |
| As a hider | вкл |
| Screen off by the proximity sensor | выкл, до последнего шага |

**Scenario** → **Pocket (E5 / E10)**, 14 шагов по подсказкам на экране:
- рука;
- передний карман: иди → стой неподвижно 2 минуты → сиди;
- задний карман; куртка; рюкзак: иди, потом стой;
- стол экраном вверх; стол экраном вниз;
- заблокированный в опущенной руке;
- последний шаг: включи **Screen off by the proximity sensor** и положи в карман, не блокируя.

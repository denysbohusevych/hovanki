# Roadmap

Что уже есть в каркасе и что осталось по [ADR 0001](adr/0001-stack.md).

## Уже работает

**`:shared`**
- Протокол (DTO, `ApiRoutes`, `protocolJson`), общий для клиента и сервера.
- TOTP-коды находки: свои SHA-1/HMAC-SHA1 на чистом Kotlin, сверены с JDK; формат QR-строки `CatchCodePayload`.
- Расписание сужающейся зоны (`ZoneSchedule.stateAt`), гео-математика.
- Правила GPS: фильтр подмены и невозможных скоростей (`LocationTrack`), решения только по нескольким точкам с accuracy ≤ 20 м, проверка зоны с запасом (`ZoneRules`), дистанция находки с учётом accuracy (`CatchRules`).
- Тесты в `commonTest` гоняются на JVM и на iOS-симуляторе.

**`:server`**
- Создание игры, вход по join-коду, старт с выбором ищущих, фазы LOBBY → HIDING → SEEKING → FINISHED по таймерам.
- Синхронизация позиций и снапшот, отфильтрованный под зрителя; раскрытия `OUT_OF_ZONE`, `MOCK_LOCATION`, `STALE_SIGNAL`.
- Выход за зону: предупреждение, таймер, выбывание.
- Находка: заявка с проверкой GPS → код TOTP (5 попыток) → автоподтверждение по таймауту → спор → голосование / правило по умолчанию.
- Хранение в памяти и удаление игр после окончания или простоя (`GameJanitor`).

**Клиент (`:clientCore`, `:composeApp`, `:androidApp`, `iosApp`)**
- Общий Compose UI для Android и iOS, Koin, навигация по состоянию.
- `GameApi` на Ktor и `GameConnection` (HTTP-опрос), `ServerClock`.
- Геолокация (FusedLocationProvider / CLLocationManager) и работа в фоне (foreground service / фоновый режим location).
- Показ кода находки и ручной ввод 4 цифр; схематичная зона на Canvas (`ZoneRadar`) вместо карты.
- Возврат в игру после перезапуска приложения: сессия в Keystore / Keychain, проверка через `sync` ([ADR 0002](adr/0002-session-storage.md)). Главный экран помнит имя игрока и адрес сервера.
- Строки интерфейса на английском, украинском и русском (Compose resources), тексты системных разрешений iOS — тоже.
- Версия, номер сборки и commit внизу главного экрана; адрес сервера по умолчанию задаётся при сборке (`hovanki.serverUrl`).

**Инфраструктура**
- CI: ktlint, тесты, сборка Android и iOS. Релиз: подписанные APK/AAB, образ сервера в GHCR, GitHub Release. Dependabot.
- Сервер в AWS: одна машина EC2 во Франкфурте, Docker Compose, Caddy с Let's Encrypt, `https://hovanki.duckdns.org` ([deploy.md](deploy.md)). Обновляется сам после каждого push в `main`. Тестовые сборки стартуют с этим адресом.
- Тестовые сборки на телефоны ([ci-cd.md](ci-cd.md#как-поставить-сборку-на-телефон)): каждый push в `main` — подписанный APK на pre-release `preview` (обновления через Obtainium) и загрузка в TestFlight. Подпись и загрузка заработают, когда в репозитории появятся секреты; до этого job'ы собирают без подписи и пишут, чего не хватает.
- E2E-тесты ([e2e.md](e2e.md)): headless-боты на коде `:clientCore` играют партии против сервера, приложение на Android-эмуляторах и iOS-симуляторе играет вместе с ботами. Оба слоя идут каждую ночь и вручную на любой ветке (`nightly.yml`); push проверяется быстро, без партий. Упавший ночной прогон открывает issue `nightly-failure`.

### Честная игра

- [ ] **«Игрок в здании»**: контуры зданий из OSM (Overpass) на сервере, предупреждение прячущемуся, раскрытие ищущим, если он явно внутри дольше минуты; решение и протокол — в [ADR 0003](adr/0003-map-and-buildings.md). Позже: ухудшение accuracy и `GnssStatus` на Android как дополнительные признаки.
- [ ] **Разбор после игры**: треки всех игроков на карте. Сервер сейчас держит только последние 5 минут трека — нужно хранить трек до конца `finished-retention` и отдать его отдельным эндпоинтом.
- [ ] **Судья-наблюдатель**: роль, которая видит всех и разбирает споры.

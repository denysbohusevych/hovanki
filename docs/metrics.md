# Метрики и данные для аналитики

Что можно знать об игроках и играх Hovanki, что уже собирается, что можно добавить и чего собирать нельзя. Решение о хранении истории и маршрутов, сроки и GDPR — [ADR 0007](adr/0007-game-history-and-routes.md).

## Уровни данных

Каждая метрика относится к одному уровню. Уровень определяет, нужно ли согласие, сколько хранить и кто видит.

| Уровень | Что это | Основание | Хранение | Кто видит |
|---|---|---|---|---|
| **A. Обезличенные** | числа об игре или системе без людей: длительность игры, сколько игроков, задержки сервера | персональных данных нет | без срока | команда |
| **B. Итоги игрока** | числа, привязанные к аккаунту, без координат: игры, победы, находки, пройденное расстояние, скорость | функция приложения («твоя статистика»), указано в политике | до удаления аккаунта | сам игрок (профиль) и команда (агрегаты) |
| **C. Геоданные** | координаты: маршруты и всё, что считается из точек, а не из итогов | явное согласие «Сохранять мои маршруты» | 90 дней | сам игрок (карта) и команда (агрегаты, без выгрузки маршрутов) |
| **Нельзя** | см. [ниже](#чего-не-собираем) | — | — | — |

Гости (без аккаунта) дают только уровень A.

Статус в таблицах:
- ✅ — уже собирается (таблица или API);
- 🧮 — можно посчитать SQL-запросом из того, что уже есть;
- ➕ — нужно добавить сбор (сервер или приложение).

## Где лежит

| Источник | Уровень | Что там |
|---|---|---|
| `played_games` | A | итоги каждой законченной игры |
| `game_results` | B | итоги игры для каждого игрока с аккаунтом |
| `game_routes` | C | точки маршрута (с согласия), 90 дней |
| `users`, `friendships`, `group_members`, `friend_requests`, `blocks`, `reports` | B | аккаунты и социальные связи ([ADR 0004](adr/0004-accounts-friends-chat.md)) |
| `GET /api/v1/me/stats`, `/me/games`, `/me/games/{id}/route` | B, C | то же самое для самого игрока в приложении |
| Лог сервера | A | счётчики очистки, ошибки; без координат, email, чата |
| e2e-отчёты (`SyncMetrics`) | A | задержки запросов в тестах, не в проде |

| Площадь, которую игрок обошёл | выпуклая оболочка точек маршрута | C | 🧮 |

| Прямолинейность пути | расстояние старт–финиш / пройдено | C | 🧮 |

## Чего не собираем

- **Координаты без согласия.** Точки игроков без «Сохранять мои маршруты» живут только в памяти и удаляются с игрой. Никаких «временных» копий в логах, бэкапах аналитики или метриках.
- **Координаты гостей** — ни в каком виде дольше игры.
- **Где человек живёт и работает.** Не выводим «дом» и «работу» из маршрутов, не ищем повторяющиеся места одного человека, не склеиваем маршруты с другими данными.
- **Чужие маршруты другим игрокам.** В приложении никто, кроме самого игрока, не видит его историю и маршруты. Разбор игры со всеми треками — только отдельным решением и с согласием всех участников.
- **Текст чата для аналитики.** Только число сообщений; текст живёт в памяти игры и в жалобах ([ADR 0004](adr/0004-accounts-friends-chat.md#9-модерация)).
- **Рекламные идентификаторы** (IDFA, AAID), контакты телефона, список приложений, сторонние SDK аналитики, которые отправляют данные третьим лицам.
- **Email и ники в выгрузках.** Для анализа хватает `user_id`.

## Кто и как смотрит

Сводные цифры (регистрации, активные игроки, игры, баланс, жалобы) показывает админка, раздел «Цифры» ([ADR 0008](adr/0008-admin.md)), по тем же правилам: средние — только по 5 играм и больше. Остальная аналитика — SQL-запросы к базе.

- **Роль только для чтения.** Отдельная роль PostgreSQL (`hovanki_analytics`, `SELECT` на нужные таблицы, без `users.email`, `users.password_hash`, `reports.text`) — чтобы запросы для аналитики не могли ничего изменить и не видели лишнего. Подключение — как сейчас, только из VM (RDS без публичного адреса).
- **Агрегаты, а не люди.** Маршруты смотреть только сводно (тепловые карты, средние по многим играм). Конкретный маршрут конкретного человека — только по его обращению (поддержка, спор) и с записью, кто и зачем смотрел.
- **Никаких выгрузок маршрутов** из базы на ноутбуки и в таблицы.
- **Маленькие выборки.** Не показывать агрегат меньше чем по 5 игрокам: по нему можно узнать конкретного человека.

## Примеры запросов

Статистика игрока (то же, что `GET /me/stats`):

```sql
SELECT count(*) AS games,
       sum(distance_meters) / 1000 AS km,
       sum(distance_meters) / nullif(sum(moving_seconds), 0) * 3.6 AS avg_kmh
FROM game_results
WHERE user_id = :user;
```

Баланс: как часто ищущие находят всех, в зависимости от числа игроков:

```sql
SELECT players,
       count(*) AS games,
       avg((hiders_caught + hiders_eliminated = players - seekers)::int) AS seekers_win_rate,
       avg(extract(EPOCH FROM finished_at - zone_started_at) / 60) AS search_minutes
FROM played_games
WHERE finished_at > now() - interval '30 days'
GROUP BY players
ORDER BY players;
```

Удержание D7 зарегистрированных за месяц:

```sql
SELECT date_trunc('week', u.created_at) AS cohort,
       count(*) AS registered,
       count(*) FILTER (WHERE EXISTS (
           SELECT 1 FROM game_results r
           WHERE r.user_id = u.id AND r.started_at >= u.created_at + interval '7 days'
       )) AS played_after_a_week
FROM users u
WHERE u.created_at > now() - interval '60 days'
GROUP BY 1
ORDER BY 1;
```

Средняя скорость прячущихся и ищущих:

```sql
SELECT role, sum(distance_meters) / nullif(sum(moving_seconds), 0) * 3.6 AS avg_kmh, count(*) AS games
FROM game_results
GROUP BY role;
```

## Что добавить дальше

По пользе для игры, сверху вниз:

1. Отказы заявок `TOO_FAR` / `NO_LOCATION`, раскрытия по причинам и их длительность — чтобы настраивать пороги GPS ([ADR 0001](adr/0001-stack.md#честная-игра)).
2. Брошенные лобби и воронка «создана → начата → закончена».
3. Отброшенные точки и распределение accuracy для всех игроков (без координат) — качество GPS по платформам.
4. Метрики сервера через Micrometer: задержки, ошибки, игроки онлайн.
5. Версия и платформа приложения в запросах — чтобы видеть проблемы конкретных сборок.
